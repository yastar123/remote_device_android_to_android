## 2. Reverse Proxy (Nginx)

File config: `/etc/nginx/conf.d/linkdroid-api.conf` (terpisah dari `xmoney.conf`, tidak saling bersinggungan)

```nginx
server {
    server_name 103-245-38-142.sslip.io;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3600s;
    }
    listen 443 ssl; # managed by Certbot
    ssl_certificate /etc/letsencrypt/live/103-245-38-142.sslip.io/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/103-245-38-142.sslip.io/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
}
server {
    if ($host = 103-245-38-142.sslip.io) {
        return 301 https://$host$request_uri;
    }
    listen 80;
    server_name 103-245-38-142.sslip.io;
    return 404;
}
```

**Poin penting untuk aplikasi:**
- Backend **wajib listen di `127.0.0.1:3000`** (bukan port lain) — nginx sudah diarahkan ke situ.
- HTTPS + sertifikat sudah aktif via Certbot, auto-renew. Aplikasi tidak perlu urus TLS sendiri.
- Header `Upgrade`/`Connection: upgrade` sudah diteruskan → **WebSocket sudah didukung** tanpa perlu tambahan config. Endpoint signaling bisa langsung pakai `wss://103-245-38-142.sslip.io/...` dan akan otomatis di-proxy ke backend di port 3000.
- `proxy_read_timeout 3600s` — koneksi long-lived (seperti WebSocket sesi remote) tidak akan diputus nginx sampai 1 jam idle.
- **Jangan ganti port 3000** tanpa mengubah file config ini juga, dan jangan edit file `xmoney.conf`.

**Yang perlu dicek/didapat sebelum dipakai di aplikasi:**
- Isi file `/etc/turnserver.conf` untuk tahu `realm`, apakah pakai `static-auth-secret` atau user/password statis, dan apakah TLS TURN (`turns:`) diaktifkan.
- Kredensial TURN ini nanti dimasukkan ke config WebRTC di sisi Android (ICE server list), contoh format:
```json
{
  "urls": "turn:103.245.38.142:3478",
  "username": "...",
  "credential": "..."
}
```
(Nilai `username`/`credential` perlu diambil dari `/etc/turnserver.conf` di VPS, belum dikonfirmasi di dokumen ini.)

## 7. Kontrak API yang Sudah Ditulis di APK

APK sudah mengirim request berikut, backend harus menyediakan endpoint yang sesuai:

**Endpoint:** `POST https://103-245-38-142.sslip.io/api/v1/devices/register`

**Body JSON:**
```json
{
  "email": "akun pengguna",
  "deviceId": "ID lokal 9 digit",
  "deviceName": "manufacturer dan model Android",
  "androidVersion": "versi Android",
  "appVersion": "versi aplikasi"
}
```

- Respons **2xx** → APK menampilkan "Device sudah terdaftar di server."
- Respons **non-2xx** (termasuk saat ini 502) → APK menampilkan gagal dan menyediakan tombol coba lagi di menu Pengaturan.
- **Belum ada access token** di request ini karena login APK masih lokal/demo — begitu auth server-side dibuat, kontrak ini perlu ditambah header `Authorization: Bearer <token>`.

## 8. Keamanan yang Perlu Diperhatikan

| Isu | Catatan |
|---|---|
| Login SSH root | 2.507 percobaan login gagal tercatat — server sedang dibrute-force dari internet. Disarankan nonaktifkan password login (`PermitRootLogin prohibit-password`), pakai SSH key, dan pasang `fail2ban`. |
| Scan bot PHP webshell | Muncul di log nginx (`das.php`, `adminan.php`, dll) ditujukan ke `taekwondo-api.signals99.com` — ini traffic bot otomatis umum di internet, bukan tanda kompromi pada domain LinkDroid, tapi menandakan server ini sering discan. |
| Secret/credential | Jangan taruh password DB, JWT secret, atau kredensial TURN langsung di source code — gunakan file `.env` yang tidak di-commit ke repo. |
